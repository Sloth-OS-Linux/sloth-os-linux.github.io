Sloth OS guides / testers

Getting started.

Sloth OS is a pre-release project. This guide explains the current state and the safest way to explore it while development continues.

Not ready for everyday use. The installer, NVIDIA path and Windows app support are still being validated on real hardware. There is no official public ISO download yet. Do not install this preview on a computer containing data you cannot afford to lose.

Before you begin

Sloth OS is built on Universal Blue's Fedora Kinoite image with KDE Plasma. It is an atomic system intended to update in the background and offer a previous deployment at boot if an update causes trouble.

  • Use a virtual machine or a spare test computer.
  • Back up anything important before changing an operating system.
  • Keep in mind that many recent changes have only been exercised in simulations or loop-device tests; the roadmap lists real-machine validation still in progress.
  • The project currently has no public ISO download or end-user USB-writing guide.

What to expect

The project is working toward a guided live system and installer. The current ISO plan boots into “Try or install Sloth OS” with a safe-graphics option. Once in the desktop, the Sloth Welcome wizard is intended to help choose a language, appearance, security preferences and apps.

Sloth OS does not preinstall a browser, office suite, media player or Steam. The welcome wizard lets you choose Flatpak apps from Flathub. The available list can change as the project develops.

Choosing apps

In the Welcome wizard, choose one or more apps in the categories you need. You can skip everything and install apps later. A browser is needed to open websites. App downloads require an internet connection and enough free storage.

Windows programs use a separate compatibility feature. Read Windows programs and games before relying on it.

Developer test path

The README describes a developer-only way to rebase a Fedora Kinoite test installation to the image built by GitHub Actions. It requires a published image in GHCR and a working build. It is not an installer, and it is not a recommended path for a primary computer.

# In a disposable Fedora Kinoite VM only:
rpm-ostree rebase ostree-unverified-registry:ghcr.io/bathorizsolt/sloth-os:latest
systemctl reboot

# After the test image has been built and signed:
rpm-ostree rebase ostree-image-signed:docker://ghcr.io/bathorizsolt/sloth-os:latest
systemctl reboot

For NVIDIA builds, the project README uses the sloth-os-nvidia image. Confirm the current image is available before attempting a rebase. The repository may be private and its package registry is not currently set up for public user access.

Updates and rollback

Sloth OS uses atomic image updates. The project aims to keep a previous working deployment available so a user can return to it from the boot menu if an update fails. Update and rollback behaviour still needs end-to-end testing before a general release.
